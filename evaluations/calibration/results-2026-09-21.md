# Astra calibration results — 2026-09-21

This was an unscored harness calibration, not evidence that Urteilskraft is universally beneficial. It tested one run per arm on four deliberately contrasted tasks with `gpt-6-astra`, `ultra` reasoning, and Codex CLI 0.155.1. The service did not expose a more specific model snapshot.

The three arms were neutral instructions, the frozen pre-change Restraint bundle, and the frozen Urteilskraft candidate. Every run used a fresh process and isolated configuration. The isolation probe passed before the successful runs. Private graders stayed outside the agent-readable namespace. Event records confirm that each conditioned run read its frozen skill and relevant references.

## Fixed private-oracle outcomes

| Task | Intended scope | Neutral | Old Restraint | Urteilskraft |
| --- | --- | ---: | ---: | ---: |
| `cal-backend-01` | Caller-specific CSV normalization | 7/7 | 7/7 | 7/7 |
| `cal-backend-02` | Shared transaction and migration invariant | 8/8 | 8/8 | 8/8 |
| `cal-fe-01` | Local responsive CSS repair | 6/6 | 6/6 | 6/6 |
| `cal-fe-02` | Structural async identity and state ownership | 6/6 | 6/6 | 6/6 |

All twelve submissions passed their fixed private graders. All backend public suites passed. All three layout submissions passed their public unit and browser suites when graded with the controller's pinned Playwright dependency tree. Old Restraint and Urteilskraft passed every public async-identity check. Neutral passed the original behavior and the private oracle but failed one self-added public assertion because a 1px control did not meet that run's new 44px target rule.

## Scope behavior observed

- On the bounded backend case, every arm normalized only the partner CSV field and preserved the strict shared parser and API.
- On the structural backend case, every arm moved booking behavior into shared transactional storage, added uniqueness enforcement, and preserved legacy rows and IDs.
- On the bounded front-end case, every arm kept the repair in CSS instead of redesigning the card.
- On the structural front-end case, every arm replaced list-position identity with stable request and file identity across the controller and views.

The calibration therefore found no evidence that Urteilskraft makes Astra default to tiny patches or refuse a justified rebuild. It also found no correctness advantage over neutral Astra or the old skill on these four fixtures. Neutral Astra was already strong enough to infer all four intended scope classes.

## Cost and uncertainty

The candidate consumed more total tokens than neutral on three of four tasks and substantially more on `cal-fe-02` (1,090,023 input tokens, 1,023,744 cached, 14,262 output) than the neutral run (741,881 input, 690,432 cached, 20,747 output). Input totals include repeated cached context and are not equivalent to billed uncached tokens. The runner did not persist a reliable monotonic duration, so this calibration supports no latency claim.

One repetition per task cannot measure stability. The tasks were authored while revising the framework and are permanently excluded from scored evidence. These results justify continuing to a blinded holdout only; they do not justify making the skill an unquestioned authority for every decision.

## Next evidence gate

Freeze a scored set of previously unseen tasks, use three repetitions per arm, anonymize diffs for two independent senior reviewers, and compare paired quality scores before cost data are revealed. Retain neutral as a real control. Reject or revise Urteilskraft if it produces a reproducible critical failure, systematic under-scoping, systematic unnecessary restructuring, or material burden without meaningful quality gain.
