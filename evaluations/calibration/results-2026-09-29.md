# Calibration results — 2026-09-29

This was an unscored calibration of the published markskill bundle (`arms/markskill-2026-09-29`, the bundle shipped in this repository's `SKILL.md` and `references/`) against a neutral control on the same four tasks used on 2026-09-21. It answers one question: does the published revision behave differently from a neutral agent on bounded and structural work? It does not establish that markskill beats neutral, and it is not the scored holdout the protocol requires.

## Harness

Two harnesses were attempted.

**Codex, WSL runner.** The frozen runner was repaired for Codex CLI 0.159: outputs must live outside `/home` and `/mnt`, the Codex bubblewrap sandbox cannot run inside the runner's namespace, and the runner gained `URTEIL_SANDBOX` and `URTEIL_CODEX_EXTRA_ARGS` hooks recorded in `run-metadata.txt`. The isolation probe passed. The first runs that reached the model were cut off by the account's usage limit, so no Codex run produced a submission. Repeated failed launches at ultra reasoning consumed part of that quota. No Codex results are reported.

**Claude Code subagents, Windows.** Each run was a fresh Opus subagent with its own copy of the task's public tree, the runner's exact prompt, and, for the markskill arm, the runner's exact skill instruction pointing at the frozen bundle. The neutral arm received no skill. Runs were one per arm per task. Hidden checks lived outside the workspaces and were never named to the agents, but no namespace enforced that boundary; isolation rested on the instruction to stay inside the workspace. Front-end runs were serialized per task because the fixtures bind fixed ports.

Grading used the task's public suite as the agent left it, the original public suite from the frozen task package, and controller-written hidden checks whose normalized SHA-256 ids are recorded in the run manifest. The 2026-09-21 private graders were not available on the grading machine, so the hidden checks are new. They were calibrated against the unmodified trees first: every check that targets the reported defect fails on baseline, and every guard check passes.

## Scope behavior observed

Both arms chose the intended scope class on all four tasks:

- `cal-backend-01`: both trimmed whitespace in the CSV importer only and left the strict amount parser and JSON API untouched.
- `cal-backend-02`: both moved booking into one shared, transactional store function behind `BEGIN IMMEDIATE`, added a unique index on `(event_id, member_id)`, and routed web, scheduled, and CLI entry points through it.
- `cal-fe-01`: both repaired the layout in CSS alone.
- `cal-fe-02`: both replaced list-position identity with stable per-entry and per-request identity.

Two qualitative differences appeared, each in one run, so they are observations and not findings:

- On `cal-fe-01`, the neutral run deleted the task's original layout test and replaced it with its own; the markskill run kept the original test and added to it.
- On `cal-fe-02`, the neutral run added a shared component while keeping both view modules; the markskill run deleted the two near-duplicate view modules and left one queue module. Both passed every check.

Verification reporting was honest in both arms. Three of four markskill runs and one neutral run proved their new tests by reverting the fix and watching them fail. The markskill `cal-fe-02` run listed what it had not verified (a real screen reader, real phone hardware).

## Claim boundary

One repetition per task on one model cannot measure stability. The tasks were authored while revising the framework and remain permanently excluded from scored evidence. The hidden checks were written by the same author as the skill. Isolation was by instruction, not by namespace.

What this calibration supports: the published markskill bundle did not cause under-scoping, unnecessary restructuring, deleted guards, or dishonest verification on these four tasks under a Claude harness, and a neutral Opus agent was already strong enough to pick the intended scope on all four. What it does not support: any claim that markskill improves correctness or scope choice. The next evidence gate is unchanged: a frozen, previously unseen 12-task set, three repetitions per arm, blinded paired review, with neutral as a real control.
